# 开发计划 2026-11-22

## 一、范围

实现 `Invest_Message` 第一版，接收飞书用户命令、维护自选与定时、按命令与定时生成 PDF 并发送。

本文档按包与模块给出开发顺序、每个模块包含的类与函数、签名与边界条件。违反文档约束需要先请求同意。

## 二、总体约定

- Python 3.14，类型注解全量书写。
- 时间一律使用 `datetime.date`，不传字符串日期。
- 跨模块传递只使用 `src/model` 中导出的数据结构。
- 包内模块之间用绝对导入：`from src.xxx import yyy`。
- 异常不跨模块边界传播；能预见的失败以返回值表达。
- 每个包实现完成后跑一次 pytest。

## 四、`src/config`

### `settings.py`

包含：

```python
class Settings:
    program_name: str          # 默认 "基金"
    port: int                  # 默认 9000
    larkbot_url: str           # 默认 "http://127.0.0.1:8000"

def get_setting() -> Setting
```

边界：

- `HEARTBEAT_SECONDS <= 0` → `SystemExit`。
- `PROGRAM_NAME` 为空字符串 → `SystemExit`。

## 五、`src/log`

### `larkbot_log.py`

负责：写 `log/larkbot.log`，记录与上游的全部往来。

包含：

```python
def receive(url: str, user_id: str, http_status: int | str, code: int | str) -> None
def send(url: str, kind: str, user_id: str, http_status: int | str, code: int | str) -> None
def register(url: str, program: str, cmd: str, path: str, program_url: str,
             http_status: int | str, code: int | str) -> None
def heartbeat(url: str, http_status: int | str, code: int | str) -> None
```

日志文件的字段顺序：

| 事件 | 顺序 |
|---|---|
| RECEIVE | 上游url · 用户id · HTTP状态 · 业务状态码 |
| SEND | 上游url · 类型 · 用户id · HTTP状态 · 业务状态码 |
| REGISTER | 上游url · 程序名 · 接口名 · 接口路径 · 程序url · HTTP状态 · 业务状态码 |
| HEARTBEAT | 上游url · HTTP状态 · 业务状态码 |

两个 url 参数：

| 参数 | 含义 | 示例 |
|---|---|---|
| `url` | 上游url，本次调用的 LarkBot 接口完整地址 | `http://127.0.0.1:8000/register` |
| `program_url` | 程序url，注册时提交的本程序地址 | `http://127.0.0.1:9001` |

状态码参数为 `int | str`：

- 正常响应与上游报错时传整数，如 `200`、`4003`。
- 超时时传字符串 `"TIMEOUT"`，两个状态码合并为一个值，只占一列。

`kind`取值：只取 `"TEXT"` 或 `"FILE"`。

### `schedule_log.py`

负责：写 `log/schedule.log`，记录定时任务的设置与触发。

- 每个模块内部维护一个文件句柄，模块加载时打开，写前 `flush()`。
- 三个模块共用同一把 `threading.Lock`，由 `__init__.py` 创建并传入，保证跨文件写入不交错。
- 每行格式为 `ISO8601时间 事件 值1 值2 …`，时间戳精确到秒，本地时间无时区后缀。
- `log/` 目录不存在时创建。

包含：

```python
def add(user_id: str, hhmm: str) -> None
def delete(user_id: str, hhmm: str) -> None
def trigger(user_id: str, hhmm: str) -> None
```

字段顺序：用户id · 计划时间。

### `task_log.py`

负责：写 `log/task.log`，记录基金获取数据与 PDF 生成。

包含：

```python
def fetch(code: str, elapsed_ms: int, result: str) -> None
def pdf(byte_size: int, elapsed_ms: int, result: str) -> None
```

字段顺序：

- FETCH 为 基金代码 · 耗时毫秒 · 结果
- PDF 为 字节数 · 耗时毫秒 · 结果。
- `result` 只取 `"OK"` 或 `"FAIL"`。

### `__init__.py`

负责：创建共享锁，初始化三个日志模块，导出 `larkbot_log`、`schedule_log`、`task_log` 三个对象。

## 七、`src/database`

### `connection.py`

负责：建立并配置数据库连接。

包含：

```python
def get_connection() -> sqlite3.Connection
```

边界：

- 每线程一条连接，用 `threading.local()` 保存。
- 参数为 `sqlite3.connect(path, timeout=5.0)`。
- 连接建立后执行 `PRAGMA foreign_keys = ON`。
- `data/` 目录不存在时创建。
- 不使用 WAL。

### `db.py`

负责：建表与三张表的全部增删改查。。

包含：

```python
def init_db() -> None
def list_watch(user_id: str) -> list[tuple[str, str]]
def add_watch(user_id: str, code: str, name: str) -> bool
def remove_watch(user_id: str, code: str) -> bool
def list_user_schedules(user_id: str) -> list[str]
def add_schedule(user_id: str, hhmm: str) -> bool
def remove_schedule(user_id: str, hhmm: str) -> bool
def list_all_schedules() -> list[tuple[str, str]]
```

边界：

- `init_db` 建三张表，语句与 `docs/project/database.md` 一致。
- `list_watch` 返回 `[(code, name), …]`，按 `rowid` 升序。
- `add_watch` 返回 `True` 表示新增、`False` 表示已存在。
- `remove_watch` 返回 `True` 表示已删除、`False` 表示不存在。
- `list_user_schedules` 返回 `["09:30", "21:00"]`，按时间升序。
- `add_schedule`、`remove_schedule` 的返回值语义同上。
- `list_all_schedules` 返回 `[(user_id, hhmm), …]`。
- 写操作使用单条短事务，事务内不做网络请求与渲染。

## 八、`src/fund`

### `fetcher.py`

负责：唯一调用 akshare 的地方，按起止日期取回一只基金的净值记录。

包含：

```python
def fetch(code: str, start_time: date, end_time: date) -> FundReport
```

边界：

- 调用 `ak.fund_open_fund_info_em(symbol=code, indicator="单位净值走势")` 一次取全量历史，再按 `start_time <= 日期 <= end_time` 过滤。
- 整个调用包在 `try/except Exception` 内。获取失败向上层报出异常。

- akshare 的单位净值接口不返回基金名称，`name` 填 `code`；名称是否覆盖由调用方决定。

## 十、`src/larkbot`

### `send.py`

负责：发送文字与文件两类消息，构造请求体与 base64 编码，统一处理超时与异常。

包含：

```python
def send_text(user_id: str, content: str) -> tuple[int, int]
def send_file(user_id: str, filename: str, content: bytes) -> tuple[int, int]
```

边界：

- 返回 `(http_status, business_code)`。
- 文件名必须带扩展名、不含控制字符；解码后不超过 30MB。
- base64 使用标准变体，不插换行。
- 每次调用写一行 `larkbot_log.send(...)`。

### `worker.py`

负责：启动时的注册与常驻心跳线程。

包含：

```python
def register_all() -> None
def start_heartbeat() -> threading.Thread
```

边界：

- `register_all` 同步调用 `/register` 四次，分别注册 `帮助`、`查询`、`自选`、`定时`，路径为 `/help`、`/query`、`/watchlist`、`/schedule`；每次写一行 `larkbot_log.register(...)`。
- `start_heartbeat` 启动 daemon 线程，循环 `sleep(settings.heartbeat_seconds)` 后调 `/heartbeat`；失败时间隔3s调用 `register_all()`。
- 心跳异常不得使线程退出。

负责：持有进程内的定时任务表，负责任务的增加、删除与到点触发。

```python
OnTrigger = Callable[[str], None]

def start(on_trigger: OnTrigger) -> None
```

```python
def route_schedule(user_id: str, args: list[str]) -> None
```

边界：

### `help.py`

负责：`基金 帮助` 的回复文本。

```python
def handle_help(user_id: str) -> None
```

### `query.py`

负责：`基金 查询` 的完整业务。区间词校验与换算、读取自选或指定代码、取数、渲染 PDF。

```python
RANGE_WORDS: dict[str, int]   # {"今天": 1, "7天": 7, "30天": 30, "1年": 365, "3年": 1095, "5年": 1826}

def handle_query(user_id: str, args: list[str]) -> None
```

边界：

- `args` 为空 → 发文字，提示至少指定一个区间词。
- `args[0]` 为六位数字 → 查指定代码，其余为区间词；否则全部视为区间词，查该用户全部自选。
- 区间词不在 `RANGE_WORDS` 中 → 发文字，列出六个合法词。
- 同一基金只调用一次 `fund.fetch`：起止日期取所有区间词中范围最大的那个，`end_time` 为今天，`start_time` 为今天减去对应自然日数。
- 折线图按区间词数量各生成一张，按范围升序；表格使用范围最大区间的数据。
- 取数成功的基金进入 PDF；失败的全部跳过。存在失败时先发一条文字列出失败基金，再发 PDF。
- 全部失败 → 只发文字。
- 自选为空 → 发文字。
- 指定代码不在自选中时不校验，直接查询。
- 文件名`基金_YYYYMMDD.pdf`。

### `watchlist_query.py`

## 十三、`src/command`

### `api.py`

负责：HTTP 入口。启动服务、校验 HTTP 参数，把请求交给 service 的路由。

```python
def create_app() -> Flask
def start() -> None
```

四条路由，处理逻辑全部转交 `service/router.py`：

| 路径 | 处理 |
|---|---|
| `POST /help` | `service.route_help(user_id, args)` |
| `POST /query` | `service.route_query(user_id, args)` |
| `POST /watchlist` | `service.route_watchlist(user_id, args)` |
| `POST /schedule` | `service.route_schedule(user_id, args)` |

边界：

- 本层校验请求体参数，不处理业务参数。
- 合法 → 立即回 `200 {"code": 0, "message": "ok"}`，写 `larkbot_log.receive(...)`，再执行处理。
- 异常不中断线程。
- 本模块不判断二级命令，不校验业务参数，不发送消息。
